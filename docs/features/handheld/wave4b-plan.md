# Handheld Wave 4b — split, cash, receipts, refunds (UI only)

Branch `handheld`. Built 2026-09-28 as **UI only**: every screen reads real
order data, and every action that would move money, change a payment record
or send a receipt goes to one stub file,
`handheld/screens/pay/unwired.ts`. Each stub shows a "not connected yet"
toast and resolves `false`, so no screen can show a success that did not
happen. Wiring a flow means replacing that function's body; the screens
already call these signatures.

Rules from Waves 1–4a still apply (see `wave4-plan.md`). The cash decision
in "Cash — why it is out" is **not** reversed by this build: the cash screen
exists, but `recordCash` stays a stub until the drawer question is answered.

## Seams (`screens/pay/unwired.ts`)

| Function | Called from | What wiring it has to answer |
| --- | --- | --- |
| `payShare(orderId, share)` | `SplitPage` (all three tabs) | Run the share through screens 7–8 with the share's amount instead of the balance; by seat / by item pass `share.items` as item coverage |
| `recordCash(orderId, { amount, tendered })` | `CashPage` | The drawer story, the closed-check guard `handlePaymentCompletion` lacks, `amountOverride` (`wave4-plan.md` → Cash) |
| `mergeChecks(targetId, sourceIds)` | `MergePage` | Ownership of the source checks, and checks that already carry payments |
| `sendReceipt(orderId, channel, to?)` | `ReceiptOptions` (screen 9) | Text / email have no handheld path; print must pin to the built-in printer, not the register's |
| `refundPayment(orderId, paymentId, { amount, reason, approvedBy })` | `RefundPage` | The register's refund path; `can_void_orders` gates nothing today (trap 9) |
| `adjustTip(orderId, paymentId, tip)` | `TipAdjustSheet` | Processor support per terminal (ATOM tip adjust) |

## Not decided by this build

- Split by item pays **whole lines**. Paying part of a multi-quantity line
  (PayForItemsView's quantity picker) is not drawn.
- By seat puts unseated lines in a "Shared" card with its own Pay; the
  register may want them spread across seats instead.
- Refund reasons are placeholders (`RefundPage` `REASONS`); swap in the
  register's list when refunds are wired.
- Merge candidates are every other open check; ownership and
  checks-with-payments are left to `mergeChecks`.
